cert-manager-webhook-arvan is installing into namespace {{ .Release.Namespace }}.

1. Check the webhook came up and its APIService is available:

   oc -n {{ .Release.Namespace }} rollout status deploy/{{ include "cert-manager-webhook-arvan.fullname" . }}
   oc get apiservice v1alpha1.{{ .Values.groupName }}

   The APIService must report AVAILABLE=True. If it does not, cainjector has
   not filled in the caBundle yet, or the Service cannot reach the pod.

2. Create the ArvanCloud api key secret (if you have not already):

   oc -n {{ .Release.Namespace }} create secret generic {{ .Values.credentialsSecretRef }} \
     --from-literal=apikey='YOUR_API_KEY'

3. Point an Issuer at this solver:

   solvers:
     - dns01:
         webhook:
           groupName: {{ .Values.groupName }}
           solverName: arvancloud
           config:
             ttl: 120
             baseUrl: "https://napi.arvancloud.ir"
             authApiSecretRef:
               name: {{ .Values.credentialsSecretRef }}
               key: apikey

   cert-manager must be able to read that secret, so the Issuer has to live in
   namespace {{ .Release.Namespace }} — or use a ClusterIssuer and put the
   secret in cert-manager's own namespace ({{ .Values.certManager.namespace }}).
